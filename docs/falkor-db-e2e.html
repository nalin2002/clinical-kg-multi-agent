2. Purpose

The project turns clinical text and structured admission facts into explicit entities and relationships so downstream tools can retrieve evidence across diagnoses, medications, procedures and findings. The broader repository also investigates whether a Graph-JEPA model can identify weak edges and recover missing relationships in LLM-drafted graphs. The intended consumers evidenced by code are engineers operating extraction and storage, researchers evaluating graph refinement, and applications asking questions about a selected admission. A named product, customer integration and clinical operating workflow are Needs confirmation: not documented; supply the consuming product and intended use boundaries.

The main E2E input is one JSON object per admission, with subject_id, hadm_id, structured lists, count fields and optional note/input_block. The output is JSONL with graph metadata, nodes and edges, plus optional note vectors; the upload maps that data into FalkorDB. QA accepts an admission identifier and question and produces answer JSON with context, prompt, model/provider and timing fields. Sources: fawkes_falkor_e2e/fawkes_falkor_e2e.py local / untracked (normalize_stage, assemble_graph, falkor_upload_stage); fawkes_falkor_e2e/fawkes_falkor_qa.py local / untracked (load_questions, main).

Small synthetic example

Input fragment (invented; no real patient):
{"subject_id":1,"hadm_id":2,"diagnoses":["Pneumonia"],
 "medications":[{"name":"Ceftriaxone"}],
 "note":"[1] Synthetic admission lists pneumonia and ceftriaxone."}

Deterministic graph fragment:
{"graph_id":"1:2","nodes":[
  {"id":"N_000","type":"PATIENT","text":"patient_1"},
  {"id":"N_001","type":"DIAGNOSIS","text":"Pneumonia"},
  {"id":"N_002","type":"MEDICATION","text":"Ceftriaxone"}],
 "edges":[
  {"source":"N_000","target":"N_001","relation":"HAS_DIAGNOSIS","confidence":1.0,"evidence":"structured"},
  {"source":"N_000","target":"N_002","relation":"TAKES_MEDICATION","confidence":1.0,"evidence":"structured"}]}

Question: "What medications are documented?"
Retrieved evidence includes: patient_1 --[TAKES_MEDICATION]--> Ceftriaxone

This is a schema illustration, not a full default-eligible input. The complete runnable example below supplies three diagnoses, three medications and one service. A MANAGED_FOR edge is inferred by the optional LLM stage; the deterministic example does not assert a treatment relationship from co-occurrence alone.

4. How the system works

Component responsibilities and contracts

Component / sourceImplemented behavior
Selection — fawkes_falkor_e2e/fawkes_falkor_e2e.py local / untracked
eligible_record, normalize_stage		Loads the entire raw JSONL into memory. An eligible patient has at least one admission with 3–40 diagnoses, 3–60 medications and ≥1 service by stored count fields. Selects up to 1,000 patient IDs using sorted IDs and seed 42; then includes all their admissions, even admissions that fail eligibility themselves. Removes note-less admissions unless --include-noteless. Count fields are not recomputed from lists. --limit-admissions applies after selection.
Nodes / deterministic edges — build_nodes, deterministic_edgesNode types: PATIENT, DIAGNOSIS, MEDICATION, PROCEDURE, MICROBIOLOGY, SERVICE, LAB_TEST. Symptoms become DIAGNOSIS nodes with presenting=true; medical history also becomes DIAGNOSIS. Names deduplicate within type, case-insensitively. Backbone: HAS_DIAGNOSIS, TAKES_MEDICATION, UNDERWENT_PROCEDURE, MANAGED_BY_SERVICE, HAD_MICROBIOLOGY, HAD_LAB_TEST. Susceptible microbiology can add TARGETS_ORGANISM for an antibiotic already represented as a medication.
Hosted inference — EndpointClient, SPECIALISTS, build_kg_stageFour requests per noted admission: MANAGED_FOR, CONFIRMS, COMPLICATED_BY, INDICATES. Default 16 worker threads; temperature 0; max_tokens 15,000; up to four attempts, 600-second per-call timeout, backoff on transient errors. Probes /v1/models and may replace configured model. required checks credentials/configuration; it does not guarantee every request succeeds.
Postprocessing — extract_json, resolve_endpoint_name, assemble_graphStrips think blocks/code fences and attempts JSON recovery. Uses only matched pairs; discards other. Resolves normalized exact names, then first substring match; drops missing/self edges and duplicate (source, relation, target) triples. Invalid confidence defaults to 0.5. Copies sentence/quote (quote capped at 300 chars). Prompt type rules and quotation support are not independently enforced here.
Embedding — embed_notes_stageTokenizes top-level note with truncation at 8,192 tokens, batch 32; attention-mask mean pools final hidden states. CUDA uses bfloat16, CPU/MPS float32. Stores rounded float vectors and embed_model, embed_dim. Empty strings are passed through the model if note-less records are included; they are not explicitly assigned a zero vector. This stage does not train ModernBERT.
Artifacts — ArtifactStoreDefault private Hub dataset; local-only mode bypasses Hub access. Stage existence is determined only by filename. JSONL writes use a temporary file then replace; uploads occur after the stage completes. No per-admission remote restart checkpoint in this standalone implementation.
Falkor upload — build_upload_rows, FalkorUploaderCreates KGGraph:Admission and KGNode:<TYPE>, optional CONTAINS_NODE edges, typed relations. Node keys are graph_id:local_node_id; default edge IDs are graph_id:E_00000 by list index. Sanitizes labels, flattens properties and skips dangling edges. MERGE runs in graph batches of 50; optional range indexes on graph_id / kg_node_id. Text fields included by default; note vectors require --include-note-embedding.
QA loading — fawkes_falkor_e2e/fawkes_falkor_qa.py local / untracked
FalkorGraphStore, resolve_graph_refs		Reads graph metadata, nodes and edges from the uploaded graph. Can select exact graph IDs or resolve subject/admission/encounter identifiers. Without IDs or limit, can select all stored graphs; provide explicit scope.
QA retrieval — retrieve_context, EmbeddingRankerDefault lexical score is token-set overlap divided by square root of token-set sizes, with tokens longer than two characters. Selects top 10 nodes; adds up to 50 incident edges in loaded order. Includes transcript turns when available, otherwise up to six lexical note/input chunks within 7,000 source chars. Optional BGE-M3 encodes node text locally; it does not use the stored ModernBERT admission vector or Falkor vector search.
QA generation / outputs — generate_answer, mainPrompt asks for evidence-bound concise answers; no enforcement or answer-quality scoring follows. Auto tries endpoint, then OpenRouter, then Ollama. Explicit provider fixes routing. Failure yields a FAILED result string; retrieve-only yields [RETRIEVE_ONLY]. Writes qa_results/<safe_id>/<safe_id>_answers.json and summary.json; answer records contain context and full prompt, so outputs inherit data access restrictions.

What changed, and what those results mean

E2E models. MedGemma drafts edges; Clinical ModernBERT embeds notes; BGE-M3 optionally ranks QA nodes; the QA provider produces text. These are four different responsibilities. None of these base LLMs/encoders is fine-tuned by the standalone folder. The actual hosted edge model is recorded in kg_raw_manifest.json after the model probe. A configured identifier alone does not prove that model served a run.

Extraction alternatives. The naive extractor uses a single draft, KARMA adds an enhancement pass and deterministic cleanup, the cooperative pipeline uses sequential roles, and EIR parallelizes entity and relation specialists. EIR’s canonicalization rewrites labels using same-type BGE-M3 similarity (documented threshold 0.70); changing the KB and prompts changes what its F1 measures. The EIR README attributes its model-swap tradeoff to lower node volume affecting population completeness; this is the document’s explanation, not a controlled causal result from this task. Anthropic support and commented model options do not establish successful evaluations.

Package v1–v4. v1 combines node-latent prediction with an edge head. v2 predicts patches; v3 adds a graph-revision objective; v4 separates JEPA pretraining from joint fine-tuning. Existing .pt files demonstrate artifact presence only. Saved configs have different relation vocabulary sizes (v2: 6; later base configs: 30; Fawkes configs: 32); version names and dimensions are not interchangeable. The root Graph-JEPA README describes an earlier seven-type/six-relation contract and its MIMIC stub, so use current source and checkpoint configuration when adapting Fawkes graphs.

Package v5. Adds masked-edge ranking with eight negatives, temperature 0.2 and default ranking weight 1.0. fawkes_v5 records 60 pretrain + 80 fine-tune epochs; fawkes_raw_v5 records 60 + 90 with confidence negatives, artifact filters and negative weight 0.6; fawkes_global_v5 records 75 pretrain epochs; fawkes_global_v5_tri_state records 75 + 80 with relation-specific confidence thresholds. These are saved configuration values, not evidence of a completed metric run. No documented reason for formally discontinuing these variants was found.

Package v6. Retains ranking and confidence logic while concatenating localized note vectors. Saved fawkes_mimic_latest_v6 uses SapBERT, 32 relations, note_ground_by=prov, 60 pretrain + 50 fine-tune epochs and negative weight 0.6. The no-note pretrain switch changes the model input contract; do not reuse a note-trained checkpoint with an incompatible shape. The package’s LOO and LLM comparison tools are separate from the paper trainer.

Paper lineage v8–v16. Source comments document the evolution from a shared world model, through v9 edge-score concatenation and a planned v10 edit head, to v11 EIR uplift and v12 LOO. v13 adds an oracle cascade evaluation and variable edge-mask schedule. v14 prunes ungrounded LLM edges and offers a score gate; v15’s added NOTE node is described as harmful; v16 moves the same note vector to existing grounded entities. A source comment is historical evidence, not proof every referenced version is available or reproducible here. The v16 handoff’s “fallback to A” means missing note features become zero in the code; there is no runtime switch to a separate no-note checkpoint.

v16 training and evaluation. Builds hashed entity IDs (8,192 slots), type embeddings and demographics plus optional note features; two TransformerConv layers, hidden 128, four heads. Sixty epochs of masked-latent JEPA pretraining use an EMA target, followed by 40 frozen-encoder readout epochs by default. Readout uses DistMult or an MLP and InfoNCE, with target relation weight 3 and mask fraction sampled from 0.1–0.6. Validation AUC selects the scorer. The default train/validation/test split permutes admission graphs, not patient groups; patient overlap across splits is therefore possible and needs audit. Unlike the later attachment lineage, the current trainer shares SEED for split and training.

Metric boundaries. LOO removes one edge before encoding, filters other true tails and ranks same-type candidates in the same graph; MRR is mean reciprocal rank and Hits@K is the fraction with rank ≤K. Candidates with insufficient alternatives are skipped, so query counts and per-relation coverage matter. Batch-mask recovery removes many edges together and is a different task. Cascade evaluation adds gold earlier-relation edges, so it is an oracle analysis, not autonomous generation. Composite KG similarity combines fuzzy entity overlap, population, relation and schema completeness; it is neither LOO MRR nor clinical answer accuracy. Package evaluators may use --candidate-mode schema by default; use the same candidate mode and held-out data for comparisons.

The package training loaders consume the graph directory supplied by the caller; they do not create a held-out split automatically. Their saved checkpoints generally contain state_dict and config, while the standalone no-note v16 checkpoint also stores evaluation aggregates. Those stored v16 scalars were inspected using archive/pickle-opcode parsing only; weights were not deserialized. The stored no-note result supports the handoff’s rounded 0.274, but does not independently verify the reported 0.419 note result.
