Graph-JEPA v3

Clinical KG Graph Revision

Version 3 reframes KG refinement as one edge-existence problem: keep true existing edges, prune bad existing edges, add missing true edges, and reject tempting but false candidate edges.

For the detailed internal pipeline, see Graph-JEPA v3 Internal Workflow.

Why v3 exists

The v2 candidate mode worked mechanically, but the scores were too permissive. On a unified graph it connected entities across unrelated encounters; on a single sub-KG it still promoted schema-valid but clinically weak edges such as unrelated x-rays confirming heart failure or absent symptoms indicating a diagnosis.

The failure mode was not random output. It was a training and candidate-space mismatch: the edge head learned broad type plausibility, while inference asked it to perform clinical graph revision.

Core idea

1. Clean KG
Start from the extracted patient graph as the best available training signal.
2. Hide edges
Remove a random subset of true edges from message passing and ask the model to score them high.
3. Inject false edges
Sample same-graph, schema-valid absent triples and ask the model to score them low.
4. Revise
Use one score for keep, prune, add, and reject decisions at inference time.

Training objective

v3 keeps the v2 patch-JEPA loss, but replaces the old edge corruption signal with a graph-revision loss.

Training example Label What it teaches
Observed true edge still visible to the encoder 1 Keep this edge.
Observed true edge hidden from message passing 1 Add this missing edge back.
Schema-valid absent edge from the same graph 0 Prune or reject this false edge.

The hard negatives are deliberately not random type violations. They are plausible-looking false triples, such as symptom-to-diagnosis or lab-to-diagnosis candidates that obey the schema but are absent from the patient graph.

Inference behavior

Existing high-score edge

Action: keep

The edge remains in the graph and receives a v3 score.

Existing low-score edge

Action: prune candidate

If --prune-threshold is passed, the edge is removed.

Missing high-score edge

Action: add candidate

The edge is appended as unverified and evidence-free.

Candidate generation is also safer by default. Unified-graph candidates must share a res_id when occurrence metadata exists, and negated or absence findings are skipped as addition sources.

Run commands

Train

PYTHONPATH=src python -m graph_jepa_v3.train \
  --data aci-bench \
  --aci-kg-path outputs/aci_bench_val/sub_kgs \
  --out ckpts \
  --encoder mock \
  --gnn-backend torch \
  --epochs 40 \
  --revision-mask-ratio 0.25 \
  --revision-neg-per-pos 3

Score, add, and prune

PYTHONPATH=src python -m graph_jepa_v3.score \
  --input outputs/aci_bench_val/sub_kgs/RES_D2N068_cooperative_multi_agent.json \
  --checkpoint ckpts/graph_jepa_v3.pt \
  --output outputs/aci_bench_val/sub_kgs/RES_D2N068_cooperative_multi_agent_v3.json \
  --add-candidates \
  --candidate-threshold 0.85 \
  --max-candidates 25 \
  --prune-threshold 0.45

Output fields

Field Meaning
jepa_score Final edge-existence score from the v3 revision scorer.
jepa_flag Coarse score band: ok, weak, or inconsistent.
jepa_revision_action keep, review, prune_candidate, or add_candidate.
jepa_suggested Present on added candidate edges only.
jepa_unverified Added candidates still require human or evidence-backed validation.

Current limits

  • v3 still does not generate transcript evidence for new edges.
  • The training signal assumes the extracted KG is mostly correct.
  • Negation filtering is lexical and conservative, not a full clinical NLP model.
  • Human review is still required before treating added candidates as curated facts.
