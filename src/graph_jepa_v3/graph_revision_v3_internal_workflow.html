Detailed internals

Graph-JEPA v3 Internal Workflow

This document explains how the v3 clinical KG revision model works from graph preprocessing through patch construction, masking, architecture, losses, candidate addition, and pruning.

Companion overview: graph_revision_v3.html

1. Goal

v3 reframes refinement as one edge-existence question:

Should this typed edge exist in this specific patient graph?

The same learned score is used for all graph revision decisions:

Case Score Action
Existing edge High Keep
Existing edge Low Review or prune
Missing edge High Add candidate
Missing edge Low Reject / ignore

The training objective combines representation learning and graph revision: 

total_loss = jepa_weight * patch_jepa_loss
           + revision_weight * edge_revision_loss

2. Graph Preprocessing

Input graphs use the shared PatientGraph JSON contract: 

{
  "nodes": [
    {"id": "N_006", "text": "shortness of breath", "type": "SYMPTOM"}
  ],
  "edges": [
    {"source_id": "N_006", "target_id": "N_001", "type": "INDICATES"}
  ]
}

In src/graph_jepa_v3/data.py, each graph is converted to a tensor object with node features, node types, edge endpoints, and edge types.

Tensor Shape Meaning
x [num_nodes, encoder_dim] Embedding of each (node.type, node.text) pair.
node_type [num_nodes] Integer schema type for each node. v3 uses this for hard negatives.
edge_index [2, num_edges] Source and target node indices for valid KG edges.
edge_type [num_edges] Integer relation ID for each edge.

Invalid tensor edges are skipped when endpoints are missing or the relation type is unknown. The original JSON is not modified during training.

Mini-batching

PyTorch Geometric batches multiple patient graphs into one object. The batch contains data.batch and data.ptr, which tell v3 where each graph begins and ends. This is important because hard negatives must be sampled inside the same patient graph, not across patients.

3. Patch Creation

Patches are created in src/graph_jepa_v3/patches.py. The default number of patches is: 

num_patches = 8
patch_pe_dim = 8

The actual number of patches is: 

actual_patches = min(num_patches, num_nodes)

So a 60-node graph gets 8 patches, while a 5-node graph gets 5 patches.

Balanced multi-source BFS

v3 partitions nodes with a balanced BFS procedure:

  1. Select seed nodes, starting with high-degree nodes and then far-apart nodes.
  2. Grow each seed into a local patch using BFS over the graph.
  3. Keep patch sizes roughly balanced.
  4. Handle disconnected components by assigning leftover nodes to the smallest patch.

Patch tensors

Object Shape / type Meaning
assignment [num_nodes] Maps every node to a patch ID.
patch_nodes list of node lists Which nodes belong to each patch.
patch_edge_index [2, num_patch_edges] Coarsened edges between patches.
patch_adj [num_patches, num_patches] Dense patch adjacency matrix.
patch_pos [num_patches, patch_pe_dim] Patch positional and structural features.

Patch positional features

Each patch gets a compact structural descriptor:

Column Feature
0 Patch size divided by total node count.
1 Patch degree divided by maximum possible patch degree.
2+ Random-walk self-return style features on the patch graph.

4. Two Kinds of Masking

v3 uses two masks, and they serve different purposes.

Patch masking

Used by the JEPA representation objective. Some patches are visible as context. Target patches have their content replaced by a learned mask token.

Edge hiding

Used by the graph-revision objective. Some true edges are hidden from message passing, then still scored as positive edges. This teaches missing-edge recovery.

Patch task sampling

Default values: 

context_patches = 1
target_patches = 4

v3 samples a connected group of target patches, then chooses nearby context patches. For an 8-patch graph: 

target patches:  [2, 3, 4, 5]
context patches: [1]
visible mask:    [False, True, False, False, False, False, False, False]

Non-visible patches keep their position but not their real content: 

if visible:
    token = patch_content + patch_position
else:
    token = mask_token + patch_position

5. Architecture

The model is implemented in src/graph_jepa_v3/model.py.

1. Node encoder Typed-edge GNN turns node text embeddings into contextual node latents.
2. Patch pooling Node latents are mean-pooled into patch latents.
3. Patch transformer Context and target branches encode patch-level structure.
4. Edge head Scores typed triples for keep, prune, add, or reject.

Typed node encoder

Each node embedding goes through a typed-edge GNN. The pure-torch backend sends both forward and reverse messages: 

source -> target message uses relation embedding
target -> source reverse message also uses relation embedding

This keeps edge direction visible while letting evidence flow both ways through a small clinical graph.

Context and target branches

v3 uses a JEPA-style online/target design:

Branch Gradient? Input visibility
Context branch Yes Masked patch content. Only context patches are visible.
Target branch No, EMA teacher Full unmasked graph.

The target branch is updated by exponential moving average: 

target_weights = decay * target_weights
               + (1 - decay) * context_weights

6. Patch-JEPA Loss

The context branch produces: 

ctx: [num_patches, latent_dim]

The target branch produces: 

tgt: [num_patches, latent_dim]

For each target patch, v3 predicts the target branch representation: 

pred_input = concat(ctx[target_patch], pos[target_patch])
pred = predictor(pred_input)
target = tgt[target_patch].detach()

The patch-JEPA loss is: 

patch_jepa_loss = smooth_l1(pred, target)
                + var_weight * variance_loss
                + cov_weight * covariance_loss

The main term asks the context branch to infer hidden target patch representations. The variance and covariance terms prevent representation collapse.

Term Purpose
smooth_l1(pred, target) Predict hidden target patch representation.
variance_loss Keep latent dimensions from becoming constant.
covariance_loss Discourage duplicate information across latent dimensions.

7. Edge Revision Loss

The edge revision objective is what makes v3 different from v2.

Default values: 

revision_mask_ratio = 0.25
revision_neg_per_pos = 3
revision_weight = 1.0

Positive edges

Existing KG edges are positives. v3 splits them into two useful cases:

Positive type How created What it teaches
Visible true edge Original edge remains in message passing. Keep good existing edges.
Hidden true edge Original edge is removed from message passing but still scored positive. Add missing true edges back.

Edge hiding

With a 32-edge graph and revision_mask_ratio = 0.25, v3 hides about 8 true edges from message passing: 

hidden = random_boolean_mask(num_edges, probability=0.25)
keep = ~hidden

z = context_node_encoder(
      data.x,
      data.edge_index[:, keep],
      data.edge_type[keep]
)

All original edges are still scored as positives afterward. Hidden edges therefore become "recover this missing edge" training examples.

Hard negative edges

v3 samples schema-valid false edges from the same graph. These are harder than random type violations.

Example true edge: 

chest x-ray -> CONFIRMS -> congestive heart failure

Possible hard negative: 

chest x-ray -> CONFIRMS -> hypertension

This negative obeys the type schema: 

PROCEDURE -> CONFIRMS -> DIAGNOSIS

but the exact triple is absent from the graph.

Edge head

The edge head scores a typed triple: 

input = concat(z_source, z_target, relation_embedding)
logit = MLP(input)
probability = sigmoid(logit)

Binary revision loss

Positives get label 1. Hard negatives get label 0. 

revision_loss = binary_cross_entropy_with_logits(logits, labels)
Training example Label Desired score
True visible edge 1 High
True hidden edge 1 High
Schema-valid absent edge 0 Low

8. One Training Step

A single batch update performs both representation learning and graph revision learning.

  1. Load one or more patient graphs as a PyG batch.
  2. Create balanced BFS patches per graph.
  3. Sample context and target patches.
  4. Run masked context branch and unmasked EMA target branch.
  5. Compute patch-JEPA prediction loss.
  6. Hide a subset of true edges from message passing.
  7. Sample schema-valid absent edges as hard negatives.
  8. Score true edges and hard negatives with the edge head.
  9. Compute binary edge revision loss.
  10. Combine losses, backpropagate, and update context model.
  11. Update target model with EMA.
loss = jepa_weight * patch_jepa_loss + revision_weight * edge_revision_loss

9. Inference and Evaluation

Scoring existing edges

At inference, v3 encodes the full graph and scores each existing edge: 

p_head = sigmoid(edge_head(z_source, z_target, relation))

It also computes a patch structural score: 

structural = exp(-patch_prediction_energy / temperature)

The final score is: 

score = alpha * p_head + (1 - alpha) * structural

v3 defaults to: 

alpha = 0.9

So the trained edge-revision head dominates the final decision.

Revision actions

Action Meaning
keep Existing edge scores high enough to keep.
review Existing edge is weak but not necessarily pruned.
prune_candidate Existing edge falls below the chosen prune threshold.
add_candidate Missing edge scored high enough to add as an unverified candidate.

Candidate addition

v3 does not create new nodes. It enumerates missing schema-valid triples between existing nodes, then filters and scores them.

  1. Enumerate source, relation, target combinations allowed by RELATION_SCHEMA.
  2. Skip triples already present in the graph.
  3. Skip negated or absence sources by default.
  4. For unified graphs, require shared res_id when occurrence metadata exists.
  5. Score each candidate with the same edge-revision score.
  6. Add candidates above candidate_threshold.

Added candidates are explicitly marked unverified: 

{
  "jepa_suggested": true,
  "jepa_unverified": true,
  "jepa_revision_action": "add_candidate",
  "jepa_source": "graph_jepa_v3_candidate_generation",
  "evidence": "",
  "turn_id": ""
}

10. Concrete Example

For a graph like RES_D2N068: 

nodes = 60
edges = 32
num_patches = 8
target_patches = 4
context_patches = 1
revision_mask_ratio = 0.25
revision_neg_per_pos = 3

One training step looks like this:

  1. Partition the 60 nodes into 8 patches.
  2. Select 4 connected target patches.
  3. Select 1 nearby context patch.
  4. Predict target patch representations from context.
  5. Hide about 8 of the 32 true edges from message passing.
  6. Score all 32 true edges as positives.
  7. Sample up to 96 schema-valid false edges as negatives.
  8. Combine patch-JEPA loss and revision loss.

Good hidden positive

decreased ejection fraction
  -> CONFIRMS
  -> pumping dysfunction

If hidden, v3 still learns to score it high. This is the add-back signal.

Hard false negative

right elbow x-ray
  -> CONFIRMS
  -> congestive heart failure

Schema-valid but clinically weak. v3 learns to score this low.

11. Why v3 Helps Compared With v2

v2 mainly learned broad edge plausibility. That allowed many candidates that were type-valid but clinically incoherent.

Problem seen in v2 v3 response
Unified graph candidates crossed unrelated encounters. Default candidate filter requires shared res_id when occurrence metadata exists.
Absent findings became positive indications. Default candidate filter skips negated/absence sources.
Schema-valid but false edges scored too high. Training uses schema-valid absent triples as hard negatives.
Addition and pruning were treated as separate modes. v3 uses one edge-existence score for keep, prune, add, and reject.

12. Current Limits

  • v3 does not generate transcript evidence for added edges.
  • Added edges should remain jepa_unverified: true until validated.
  • The training signal assumes the extracted KG is mostly correct.
  • Negation handling is lexical and conservative, not a full clinical NLP model.
  • If the original KGs contain systematic mistakes, v3 can learn those mistakes.

The intended use is therefore: 

v3 suggests keep / review / prune / add decisions
human or evidence-backed validation decides final curated graph
