Graph-JEPA v4

Staged Clinical KG Graph Revision

Version 4 keeps the v3 graph-revision framing, but trains it in two stages and makes the edge objective schema-aware. The model first learns masked graph representations, then fine-tunes on keep, prune, add, and reject decisions with stronger negative examples.

For the detailed internal pipeline, see Graph-JEPA v4 Internal Workflow.

Why v4 exists

v3 fixed the main v2 failure mode by turning refinement into a single edge-existence problem. It could score existing edges, prune weak edges, and add missing candidates with one learned edge head.

v4 addresses the next two issues. First, joint training asks the same model to learn masked patch representations and edge revision at the same time, so the revision loss can shape the representation before the patch encoder is stable. Second, extracted or adapted KGs can contain typed edges that violate the clinical relation schema. v3 treated those observed edges as positives; v4 treats them as explicit evidence of what not to learn.

Core idea

1. Sanitize
Remove typed-invalid edges from message passing so the encoder does not propagate through known-bad directions.
2. Pretrain
Train masked patch prediction by itself and save graph_jepa_v4_pretrain.pt.
3. Fine-tune
Resume from the pretrain checkpoint and train JEPA plus graph revision.
4. Revise
Score existing edges and high-confidence missing candidate edges.
5. Guard
Force schema-invalid scored edges to inconsistent during inference.

Training setup

v4 splits training into two explicit commands. Both commands share the same data options: synthetic, mimic, mimic-subkgs, and aci-bench.

1. Masked pretraining

PYTHONPATH=src python -m graph_jepa_v4.pretrain \
  --data aci-bench \
  --aci-kg-path outputs/aci_bench/sub_kgs \
  --out ckpts \
  --encoder mock \
  --gnn-backend pyg \
  --epochs 50

2. Joint fine-tuning

PYTHONPATH=src python -m graph_jepa_v4.finetune \
  --data aci-bench \
  --aci-kg-path outputs/aci_bench/sub_kgs \
  --checkpoint ckpts/graph_jepa_v4_pretrain.pt \
  --out ckpts \
  --epochs 50 \
  --revision-mask-ratio 0.25 \
  --revision-neg-per-pos 3

3. Score, add, and prune

PYTHONPATH=src python -m graph_jepa_v4.score \
  --input outputs/aci_bench_val/sub_kgs/RES_D2N068_cooperative_multi_agent.json \
  --checkpoint ckpts/graph_jepa_v4.pt \
  --output outputs/aci_bench_val/v4_scored/RES_D2N068_cooperative_multi_agent_v4.json \
  --add-candidates \
  --max-candidates 50 \
  --prune-threshold 0.45

End-to-end ACI-Bench wrapper

GRAPH_JEPA_MODULE=graph_jepa_v4 \
GRAPH_JEPA_CKPT=ckpts/graph_jepa_v4.pt \
./run_aci_bench.sh

What the model learns

Training signal Label Purpose
Schema-valid observed edge 1 Keep valid existing edges and recover hidden true edges.
Schema-valid absent edge from the same graph 0 Reject plausible but unsupported clinical triples.
Observed typed-invalid edge 0 Teach the model not to trust extraction artifacts just because they are present.
Reversed edge that violates the schema 0 Teach directionality, such as medication treating diagnosis rather than diagnosis treating medication.

The revision loss is relation-balanced, so frequent relation types do not dominate rare but clinically important relation decisions.

Inference behavior

Existing high-score edge

Action: keep

The edge remains in the graph and receives a v4 score.

Existing low-score edge

Action: review or prune

If --prune-threshold is passed, the edge is removed.

Schema-invalid edge

Action: inconsistent

The schema guard caps the score at schema_invalid_score.

Candidate generation reuses the v3 safe defaults: relation-specific thresholds, same-patient candidate constraints when res_id metadata exists, and conservative skipping of negated or absent findings.

Output fields

Field Meaning
jepa_score Final edge-existence score after v4 scoring and schema guarding.
jepa_flag Coarse score band: ok, weak, or inconsistent.
jepa_revision_action keep, review, prune_candidate, or add_candidate.
jepa_schema_valid Whether the edge type and endpoint node types pass the clinical relation schema.
jepa_schema_error Present when an existing edge violates the schema.
jepa_source Added candidates use graph_jepa_v4_candidate_generation.

Improvements over v3

Area v3 v4 improvement
Training schedule Joint JEPA and revision training in one script. Two-stage masked pretraining followed by joint fine-tuning.
Schema-invalid observed edges Observed edges were treated as positives if they were in the graph. Typed-invalid observed edges are removed from message passing and trained as negatives.
Directionality Relied mostly on relation embeddings and sampled negatives. Adds reversed schema-invalid negatives for stronger directed-edge learning.
Class balance Binary BCE over all revision examples. Relation-balanced BCE averages relation and label cells.
Scoring safety Could assign high scores to edges that violated type schema. Schema guard marks invalid edges as inconsistent and caps their score.
Checkpoints Single final checkpoint. Separate pretrain and final checkpoints make experiments easier to resume and compare.

Current limits

  • v4 still does not generate transcript evidence for added candidate edges.
  • The schema guard checks type compatibility, not full clinical truth.
  • Added candidates remain unverified and should be reviewed before curation.
  • The model still depends on the quality and coverage of the source KGs used for training.
