Detailed internals

Graph-JEPA v5 Internal Workflow

This document follows the v5 clinical KG revision pipeline from JSON metadata conversion through schema and confidence sanitation, masked pretraining, tri-state revision learning, hidden-edge candidate ranking, schema-guarded scoring, candidate addition, and pruning.

Companion overview: graph_revision_v5.html

1. Goal

v5 keeps the edge-existence question used by v3 and v4:

Should this typed edge exist in this specific patient graph?

It adds a second question that more closely matches candidate generation:

Does the hidden true edge rank above nearby schema-valid alternatives?

During joint fine-tuning, the model optimizes three terms: 

total_loss = jepa_weight * patch_jepa_loss
           + revision_weight * relation_balanced_revision_bce
           + ranking_weight * candidate_ranking_cross_entropy

2. Version Stack

v5 is intentionally incremental. It subclasses or imports the stable parts of earlier versions instead of copying the full implementation.

3. Graph Conversion

src/graph_jepa_v5/data.py delegates the standard tensor conversion to v4, then creates three aligned edge tensors.

Tensor Shape Meaning
edge_llm_confidence [num_edges] Finite numeric confidence, or NaN when absent or invalid.
edge_is_llm [num_edges] True only when the edge evidence string equals llm, case-insensitively.
edge_clinical_artifact [num_edges] True when either endpoint matches a known administration or cancelled-microbiology artifact.

These tensors are appended only for edges retained by the base converter, so their order stays aligned with edge_index and edge_type, including after PyG batching.

Current artifact rules

  • Medication nodes named bag, syringe, or vial.
  • Medication text containing flush, sterile water, mini bag plus, iso-osmotic dextrose, or syringe.
  • Microbiology nodes named cancelled.

Detection and use are separate. Metadata is always created, but it only changes fine-tuning when --clinical-artifact-filters is enabled.

4. Edge Sanitation and Tri-State Masks

Schema sanitation

v5 inherits sanitized_graph_data from v4. Typed-invalid edges are removed from message passing. Unconstrained relations such as ASSOCIATED_WITH and CO_OCCURS_WITH can remain in the message graph, but they are not typed positive labels. 

schema_valid, schema_invalid, unconstrained = _schema_edge_masks(data)
schema_message_mask = schema_valid | unconstrained

Confidence masks

_confidence_supervision_masks returns three disjoint masks: trusted positives, weak negatives, and ignored edges.

Condition Mask Behavior
Non-LLM edge, or LLM confidence at or above the positive cutoff trusted_positive Can enter message passing and positive labels.
LLM confidence at or below the negative cutoff weak_negative Excluded from messages and added to BCE negatives.
LLM confidence strictly between both cutoffs ignored Excluded from messages, positives, and negatives.
Artifact edge when artifact filtering is enabled weak_negative Overrides normal structured-positive treatment. 
low = scored_llm & (confidence <= negative_cutoff)
high = scored_llm & (confidence >= positive_cutoff) & ~low
ignored = is_llm & ~low & ~high

trusted_positive = (~is_llm | high) & ~artifact
weak_negative = (low | artifact) & ~trusted_positive

The global fallback cutoffs are 0.3 and 0.8. Relation-specific maps can replace either cutoff for relations such as CONFIRMS, INDICATES, and MANAGED_FOR.

5. Architecture

GraphJEPAv5 subclasses GraphJEPAv4. No new neural module is added; v5 changes how the existing edge head is trained.

Typed node encoder

Encodes node text features with relation-aware GNN message passing on the sanitized edge set.

Patch JEPA

Pools nodes into balanced graph patches, predicts hidden target representations, and updates the target branch by EMA.

Shared edge head

Scores (source latent, target latent, relation embedding) for both revision BCE and candidate ranking. 

edge_logit = edge_head(z_source, z_target, relation_id)
edge_probability = sigmoid(edge_logit)

6. Stage 1 Pretraining

graph_jepa_v5.pretrain trains only the masked patch objective. The checkpoint is written as graph_jepa_v5_pretrain.pt. 

use_revision = False
loss = jepa_weight * patch_jepa_loss
  1. Load a patient-graph batch with aligned confidence metadata.
  2. Remove schema-invalid typed edges.
  3. Remove LLM edges at or below the relation-specific negative cutoff.
  4. Keep middle-confidence and high-confidence LLM edges for pretraining.
  5. Build balanced BFS patches from the resulting message graph.
  6. Predict masked target-patch representations and update the EMA branch.

Important pretraining detail

The current v5 pretraining path always applies the low-confidence LLM removal when confidence metadata exists. It does not require the fine-tuning --llm-tri-state-supervision flag, and it does not apply the clinical artifact mask.

7. Stage 2 Fine-tuning

graph_jepa_v5.finetune loads the masked-pretrained checkpoint and jointly optimizes JEPA, revision BCE, and candidate ranking. 

model, cfg = load_model_checkpoint(pretrain_checkpoint)

loss = cfg.train.jepa_weight * jepa
     + cfg.train.revision_weight * revision
     + cfg.train.ranking_weight * ranking

The message graph depends on the selected supervision mode:

Flags Fine-tuning message graph Observed-edge labels
Neither flag Schema-valid and unconstrained edges. Legacy v4 behavior: schema-valid observed edges are positive.
--llm-tri-state-supervision Schema-valid trusted positives and unconstrained trusted edges. High positive, low weak negative, middle ignored.
--clinical-artifact-filters Schema-valid non-artifact edges. Artifact edges become weak negatives.
Both flags Only schema-valid, confidence-trusted, non-artifact messages. Combines confidence tri-state and artifact weak negatives.

8. Confidence-Aware Revision Loss

v5 keeps v4 relation-balanced BCE, but changes which observed edges are positive and adds optional weak-negative weighting.

Positive examples

pos_mask = schema_valid & trusted_positive

A random subset is hidden from message passing using revision_mask_ratio, but every selected positive is still scored with label 1.

Negative examples

Negative source Origin Default weight
Schema-valid absent triple Sampled from the same graph. 1.0
Observed schema-invalid edge Present in the source KG but type-incompatible. 1.0
Reversed schema-invalid edge Directionally invalid reverse of a positive. 1.0
Low-confidence LLM edge At or below its negative cutoff. llm_negative_weight = 0.2
Clinical artifact edge Matches the optional artifact mask. llm_negative_weight = 0.2

Weighted relation balancing

BCE is computed per edge. Examples are grouped by relation and label, weak-negative weights are applied inside each cell, then relation losses are averaged. 

for relation in unique(relations):
    positive_cell = mean(bce_positive * positive_weights)
    negative_cell = mean(bce_negative * negative_weights)
    relation_loss = mean(non_empty_cells)

revision_loss = mean(relation_losses)

9. Hidden-Edge Candidate Ranking

The ranking objective is the defining v5 addition. It creates a local candidate list around each hidden trusted positive and asks the existing edge head to place the true edge first.

1. Select hidden positives

positive_indices = indices(schema_valid & trusted_positive)
hidden_count = round(ranking_mask_ratio * positive_count)
hidden_count = clamp(hidden_count, minimum=1, maximum=ranking_max_pos)

Defaults are ranking_mask_ratio = 0.25 and ranking_max_pos = 256.

2. Build hard distractors

For each hidden edge (source, target, relation), v5 collects up to ranking_neg_per_pos = 8 absent, schema-valid triples from three buckets.

Bucket Fixed components Varied component
Target distractors Source and relation Another type-compatible target in the same patient graph.
Source distractors Relation and target Another source whose type permits that target.
Relation distractors Source and target Another relation allowed for those endpoint types.

Existing graph triples are excluded. Sampling stays within graph bounds in a PyG batch, so distractors never cross patient graphs.

3. Hide and encode

message_mask = (schema_valid | unconstrained)
             & trusted_positive
             & ~hidden_positive_mask

z = context_node_encoder(
    data.x,
    data.edge_index[:, message_mask],
    data.edge_type[message_mask],
)

4. Rank with temperature-scaled cross entropy

candidate_logits = [positive_logit, negative_logit_1, ..., negative_logit_k]
target_class = 0
ranking_loss = cross_entropy(candidate_logits / temperature, target_class)

The default temperature is 0.2. Losses are averaged across hidden positives that have at least one available distractor.

10. Inference and Graph Revision

v5 scoring delegates to the v4 scorer. Confidence metadata changes the learned weights during training, but the inference formula and schema guard are unchanged. 

p_head = sigmoid(edge_head(z_source, z_target, relation))
structural = exp(-patch_prediction_energy / energy_temperature)
score = alpha * p_head + (1 - alpha) * structural

The default alpha is 0.9. After scoring, v4's schema guard marks incompatible typed edges as jepa_schema_valid: false, records jepa_schema_error, caps their score, and sets the flag to inconsistent.

Candidate addition

  1. Enumerate absent triples allowed by the relation schema.
  2. Apply same-encounter and negation filters unless explicitly disabled.
  3. Score candidates with the same edge head and patch-energy formula.
  4. Apply relation-specific candidate thresholds.
  5. Keep the highest scoring candidates up to max_candidate_edges.

The current v5 scorer calls v4 candidate-generation helpers directly. Consequently, added edges currently record jepa_source: graph_jepa_v4_candidate_generation. This is an implementation inheritance marker, not a separate v4 scoring pass.

11. Commands and Metrics

Pretrain on Fawkes MIMIC train graphs

PYTHONPATH=src python -m graph_jepa_v5.pretrain \
  --data mimic-subkgs \
  --mimic-subkg-path outputs/fawkes_mimic_graphs_4k_5k/sub_kgs/train \
  --out ckpts/fawkes_global_v5 \
  --encoder mock \
  --gnn-backend pyg \
  --epochs 40

Fine-tune with tri-state and artifact supervision

PYTHONPATH=src python -m graph_jepa_v5.finetune \
  --data mimic-subkgs \
  --mimic-subkg-path outputs/fawkes_mimic_graphs_4k_5k/sub_kgs/train \
  --checkpoint ckpts/fawkes_global_v5/graph_jepa_v5_pretrain.pt \
  --out ckpts/fawkes_global_v5 \
  --epochs 40 \
  --revision-weight 1.0 \
  --ranking-weight 1.0 \
  --ranking-mask-ratio 0.25 \
  --ranking-neg-per-pos 8 \
  --llm-tri-state-supervision \
  --clinical-artifact-filters

Override confidence thresholds for one relation

--llm-negative-threshold-relation CONFIRMS=0.65 \
--llm-positive-threshold-relation CONFIRMS=0.95

Score and add candidates

PYTHONPATH=src python -m graph_jepa_v5.score \
  --input outputs/fawkes_mimic_graphs_4k_5k/sub_kgs/test \
  --checkpoint ckpts/fawkes_global_v5/graph_jepa_v5.pt \
  --output outputs/fawkes_mimic_graphs_4k_5k/sub_kgs_revised_v5 \
  --add-candidates \
  --max-candidates 50

Metric Interpretation

train/ranking_pos, train/ranking_neg Positive ranking groups and distractors used per batch.
train/ranking_llm_excluded Low or uncertain LLM edges excluded from ranking positives.

12. Limits

  • Confidence thresholds encode a training policy; they do not prove that an edge is clinically correct or incorrect.
  • Artifact detection is deliberately narrow and lexical, so it will miss unlisted artifacts and may need dataset-specific updates.
  • The ranking objective only considers existing graph nodes and relations allowed by the current schema.
  • Graphs with no available hard distractors do not contribute a ranking group for that hidden edge.
  • Inference still uses v4 scoring logic and does not directly consume edge confidence.
  • Added candidates remain evidence-free and unverified until a downstream validation step accepts them.
