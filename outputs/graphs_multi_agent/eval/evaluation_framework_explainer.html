No-Reference Clinical KG Evaluation Framework

A practical metric suite for comparing raw patient knowledge graphs with Graph-JEPA revised graphs when no silver or clinician-curated reference graph is available.

What This Framework Is For

The goal is to evaluate whether a graph revision layer improved or degraded each patient knowledge graph. Because there is no clinical gold reference, this framework does not measure true clinical accuracy. Instead, it measures whether the revised graph is more structurally plausible, better grounded in evidence fields, less duplicated, and more consistent with the typed clinical relation schema and JEPA edge scores.

Read the final number as a no-reference proxy for graph quality and revision behavior. It is useful for comparing versions, but it should not be described as clinical correctness without a manual or silver-reference audit.

Evaluation Unit

Metrics are computed separately for each patient graph. After that, the patient-level numbers are averaged. This is the macro-average protocol. It prevents very large patient graphs from dominating the result. 

For each matched patient:
  input_score_i  = score(input_graph_i)
  revised_score_i = score(revised_graph_i)
  delta_i = revised_score_i - input_score_i

Final report:
  macro_input_score   = mean(input_score_i)
  macro_revised_score = mean(revised_score_i)
  macro_delta         = mean(delta_i)
  patients_improved   = count(delta_i > 0)
  patients_degraded   = count(delta_i < 0)

Graph Matching

Input and revised graph files are matched by filename stem. For example, 10001401.json in the input directory is compared with 10001401.json in the revised directory.

Edge matching is ID-independent when possible. Each edge is normalized into this comparison key: 

(source_type,
 source_normalized_name_or_name,
 relation,
 target_type,
 target_normalized_name_or_name,
 hadm_id)

This makes the comparison robust to differences such as source versus source_id, relation versus type, and node ID renumbering.

Core Metrics

Metric Definition Interpretation
schema_valid_rate Schema-valid edges divided by total edges. Higher means relations obey expected clinical source/target types.
evidence_coverage Edges with non-empty evidence divided by total edges. Higher means facts are more traceable to source context.
core_relation_rate Edges using clinically central relations divided by total edges. Higher means the graph is focused on useful clinical facts.
duplicate_edge_rate Duplicate normalized edge keys divided by total edges. Lower means less repeated graph noise.
connectedness_score Nodes touched by at least one edge divided by total nodes. Higher means fewer orphan nodes.
mean_jepa_score Average jepa_score across scored edges. Higher means JEPA finds the edges more plausible.
ok_edge_rate Edges with jepa_flag == "ok" divided by total edges. Higher means more edges pass the JEPA plausibility threshold.
score_coverage Edges with jepa_score divided by total edges. Determines whether JEPA-based quality is fair to use.

Structural Quality Score

Structural quality is the fallback score that works on both raw and JEPA-scored graphs. It uses only fields that should exist in any graph: nodes, edges, relation labels, node types, evidence, and graph structure. 

structural_quality =
  0.40 * schema_valid_rate
+ 0.25 * evidence_coverage
+ 0.15 * core_relation_rate
+ 0.10 * (1 - duplicate_edge_rate)
+ 0.10 * connectedness_score

What It Represents

A no-reference estimate of whether a patient graph is well-formed, clinically focused, grounded, and not obviously noisy.

Why It Exists

Raw input graphs usually do not have jepa_score, so they cannot be fairly compared using a JEPA-only score.

JEPA Quality Score

JEPA quality uses the same basic graph quality signals plus JEPA's learned plausibility judgments. It is only used when both compared graphs have enough scored edges. 

jepa_quality =
  0.30 * mean_jepa_score
+ 0.25 * schema_valid_rate
+ 0.20 * ok_edge_rate
+ 0.15 * evidence_coverage
+ 0.10 * (1 - duplicate_edge_rate)

The default requirement is score_coverage >= 0.95. If the raw input graph is unscored and the revised graph is scored, the paired comparison uses structural_quality so both sides are judged by the same kind of evidence.

Revision Utility Score

Revision utility measures whether the JEPA layer behaved like a useful graph revision system, not just whether the final graph looks cleaner. This matters because a model can inflate average quality by deleting difficult edges. 

revision_utility =
  0.40 * revised_eval_score
+ 0.25 * good_input_edge_retention
+ 0.25 * bad_input_edge_removal
+ 0.10 * new_edge_quality
Component Meaning
revised_eval_score The final graph should itself be high quality.
good_input_edge_retention Good input edges should not be deleted.
bad_input_edge_removal Bad input edges should be removed or flagged out of the final graph.
new_edge_quality New JEPA-added edges should be plausible, schema-valid, and high scoring.

How Edges Are Classified

For revision accounting, input edges are categorized as good, bad, or neutral. This classification is intentionally simple and conservative. 

bad edge:
  schema invalid
  OR jepa_flag == "inconsistent"

good edge:
  schema valid
  AND jepa_flag == "ok"

neutral edge:
  schema valid
  AND jepa_flag == "weak"

If a raw input edge has no JEPA annotations, a schema-valid edge is treated as good for retention accounting. This prevents the revision layer from being rewarded for deleting unscored but structurally valid input facts.

Clinical Relation Focus

The framework gives credit for retaining and producing core clinical relations. In the MIMIC-style graph setting, these include:

HAS_DIAGNOSIS TAKES_MEDICATION UNDERWENT_PROCEDURE HAD_LAB_TEST HAD_MICROBIOLOGY MANAGED_BY_SERVICE TREATED_BY DIAGNOSED_BY MONITORED_BY PERFORMED_FOR

This is still not clinical ground truth. It is a way to avoid rewarding graphs that are formally valid but filled with low-value or peripheral facts.

How To Interpret Outcomes

Observed Result Likely Meaning
Higher revised score and high core retention JEPA probably cleaned noise while preserving useful clinical content.
Higher revised score but low core retention JEPA may be over-pruning clinically important facts.
Lower revised score and many added edges Candidate generation may be adding noisy or poorly grounded edges.
High structural score but low JEPA quality The graph is well-formed, but JEPA does not find the edges plausible.
High JEPA quality but low evidence coverage The graph may be plausible but insufficiently grounded.

Limitations

This framework cannot prove that a diagnosis, medication, lab, or procedure is clinically correct. It can only estimate quality from graph structure, schema consistency, evidence presence, duplicate behavior, and model plausibility.

For a true clinical quality score, add one of the following:

  • A clinician-reviewed edge sample.
  • A silver reference from structured MIMIC tables.
  • A task-based downstream evaluation, such as retrieval or QA over the graph.

Suggested Audit Add-On

To calibrate the no-reference score, sample 50 to 100 edges from each graph version and label: 

supported_by_evidence: yes / no
clinically_meaningful: yes / no
relation_correct: yes / no
right_admission_context: yes / no

Report sampled precision next to the automatic metric. This gives readers a bridge between the proxy score and real clinical correctness.

Command Used By The Framework

The implemented evaluator can produce the quantitative CSV and JSON outputs with: 

PYTHONPATH=src python -m eval.clinical_kg \
  --input-dir outputs/graphs_multi_agent/sub_kgs \
  --revised-dir outputs/graphs_multi_agent/v4_scored \
  --out-dir outputs/graphs_multi_agent/eval

The key output files are patient_metrics.csv, input_graph_metrics.csv, revised_graph_metrics.csv, and summary.json.
