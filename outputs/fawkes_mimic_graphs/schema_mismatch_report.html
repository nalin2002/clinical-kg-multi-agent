Dataset Audit

Fawkes MIMIC Schema Mismatch Report

Structural and semantic mismatch notes for the MIMIC-style sub-KG JSONs in outputs/fawkes_mimic_graphs/sub_kgs, focused on Graph-JEPA v4 training and finetuning compatibility.

Executive Summary

1000 graphs analyzed
46,345 nodes
68,498 edges
28.5% schema-invalid edges
Main issue: the graphs are syntactically loadable, but several high-volume relation/type combinations do not match the v4 typed relation schema. During v4 finetuning, these observed edges are treated as negatives rather than positives.

The corpus has no dangling edges, duplicate edge triples, duplicate node ids, or self-loops. Every graph is connected. The mismatch is semantic: v4 expects specific source and target node types for each relation, while this dataset uses some relations with different clinical meanings.

How v4 Interprets Edges

Graph-JEPA v4 checks each edge against RELATION_SCHEMA. A typed edge is valid only when (source_type, relation) -> target_type is allowed by the schema.

In training, v4 builds patch/message-passing inputs from sanitized_graph_data. Schema-invalid edges are removed from message passing. In the revision loss, schema-valid observed edges become positives, while schema-invalid observed edges become explicit negatives.

This behavior is useful when invalid edges are truly wrong. It is harmful when the dataset contains clinically meaningful edges whose relation label or node type disagrees with the schema.

Mismatch Patterns

1. Medication treatment edges are labeled as service-management edges

Observed Pattern Count Example Why v4 Rejects It
MEDICATION -MANAGED_FOR-> DIAGNOSIS 14,543 furosemide -MANAGED_FOR-> hypertension v4 currently allows SERVICE -MANAGED_FOR-> DIAGNOSIS, not medication-source management.
MEDICATION -MANAGED_FOR-> MICROBIOLOGY 27 vancomycin -MANAGED_FOR-> MRSA The likely meaning is antimicrobial coverage, closer to TARGETS_ORGANISM.
MEDICATION -MANAGED_FOR-> PROCEDURE 14 oxycodone -MANAGED_FOR-> total knee replacement The likely meaning is post-procedure symptom or pain management, but target type is not schema-compatible.

Recommended repair: convert clear medication-diagnosis treatment links to DIAGNOSIS -TREATED_BY-> MEDICATION, or add an explicit medication-source relation if that direction is desired.

2. Presenting symptoms are typed as diagnoses

Observed Pattern Count Example Why v4 Rejects It
DIAGNOSIS -INDICATES-> DIAGNOSIS 4,715 other ascites -INDICATES-> peritoneal abscess v4 expects SYMPTOM -INDICATES-> DIAGNOSIS or LAB_RESULT -INDICATES-> DIAGNOSIS.

The source concepts often come from _patient.symptoms and appear as nodes with presenting: true, but their node type remains DIAGNOSIS. In this corpus, 552 graphs have patient symptoms and 968 presenting nodes are typed as DIAGNOSIS.

Recommended repair: when a node is a presenting symptom, use type: "SYMPTOM" for training while preserving the original raw type in a field such as mimic_type.

3. Cross-type clinical edges need schema decisions

Observed Pattern Count Example Decision Needed
PROCEDURE -COMPLICATED_BY-> DIAGNOSIS 49 knee replacement -COMPLICATED_BY-> urinary retention May be clinically meaningful; add schema support or remap carefully.
MEDICATION -CONFIRMS-> DIAGNOSIS 56 insulin -CONFIRMS-> type 2 diabetes Likely treatment evidence, not confirmation. Consider remapping to treatment relation.
PROCEDURE -CONFIRMS-> MICROBIOLOGY 9 biopsy -CONFIRMS-> streptococcus pneumoniae Could be valid if microbiology is treated as a result/organism target, but current schema does not allow it.

Clinical Coverage Gaps

  • No lab-test signal: the corpus has 0 LAB_TEST nodes and 0 lab-test edges.
  • Medication-heavy graph shape: MEDICATION nodes are 26,706 / 46,345 nodes.
  • Patient-star topology: about 66% of edges originate from PATIENT, so cross-clinical reasoning relies heavily on the LLM-derived edge layer.
  • Medical history collapse: 2,895 medical-history items appear as diagnosis nodes, including prior use/status/history concepts.

Training Risk

Stage Risk Reason
v4 pretraining Usable with caveats Invalid semantic edges are removed from message passing, reducing the useful cross-clinical graph signal.
v4 finetuning Do not run as-is Many clinically intended edges would be learned as negative examples because of schema/type mismatch.

Residual Mismatches After Repair

The repaired conversion output in outputs/fawkes_mimic_graphs/sub_kgs_repaired contains 1000 graphs split into 950 train graphs and 50 test graphs. The conversion-time repairs reduced strict schema-invalid edges from 19,489 to 1,947. Another 1,748 edges are now intentionally unconstrained, mostly ASSOCIATED_WITH or CO_OCCURS_WITH, and are not counted as strict invalids.

64,803 schema-valid edges

Remaining invalids are mostly LLM-derived edges where the relation label is still too broad for the current v4 typed schema, or where a source/target type pair needs a deliberate clinical policy.

Recommended Repair Order

  1. Retype presenting symptom nodes from DIAGNOSIS to SYMPTOM for training, preserving the raw type.
  2. Remap medication-treatment edges from MEDICATION -MANAGED_FOR-> DIAGNOSIS to a schema-compatible treatment relation.
  3. Decide whether procedure complication and microbiology confirmation patterns should expand RELATION_SCHEMA.
  4. Add or recover LAB_TEST nodes before evaluating lab-aware v4 behavior.
  5. Split train/validation/test by subject_id, since 64 subjects have multiple admissions.
